# PLANRO — PROVINCE TEXT REWRITE (Human Prose + Brand Voice)

این پرامپت را **بعد از تکمیل تحقیق استان** و **قبل از** `05-final-audit-minify` اجرا کن.

هدف دوگانه:
1. متن کاربرمحور را از نو بنویس (نه کپی منبع، نه ردپای OTA).
2. خروجی باید مثل نوشتهٔ یک ادیتور انسانیِ گردشگریِ فارسی باشد؛ **هیچ‌کس نباید حس کند متن با AI تولید شده است.**

قرارداد ساختاری در `01-start-province.txt` است؛ این پرامپت فقط لایهٔ **متن** را اصلاح می‌کند.

### RUN VARIABLES
```text
province_id=<PROVINCE_ID>
text_rewrite=true
```
اگر `province_id` واقعی در Task آمده باشد همان authoritative است؛ وگرنه `MISSING_INPUT: province_id` بده و متوقف شو.

## 0) منابع اجباری قبل از نوشتن
1. `planro://rules/brand-voice-guide` (مرجع لحن)
2. `planro://rules/entity-fields`
3. خروجی‌های `output/{province_id}/` + notes همان استان

سؤال تعاملی نپرس. دادهٔ ساختاری را برای «زیباتر شدن متن» جعل نکن.
در گزارش نهایی و commit message ننویس که متن «با AI بازنویسی شد».

## 1) چه چیزی بازنویسی می‌شود (الزامی)
برای **هر** Entity فعال در `output/`:

- `content.summary.fa` / `.en` (اگر en خالی است و داده کافی است، بنویس؛ اگر منبع انگلیسی معتبر نیست، خالی نساز)
- `content.description.fa` / `.en`
- `content.whyVisit`
- `content.history` / `architecture` / `culture` اگر وجود دارند
- `seo.title` / `seo.description` / `seo.keywords` (keywords را از متن تمیز بساز؛ برند پلتفرم نگذار)
- `faq[].question` / `faq[].answer`
- `tips[]`
- `warnings[].text`
- `culturalNotes` (اگر متن آزاد دارد)
- `media.thumbnail.alt` / `caption` و همین‌طور برای `images[]` / `videos[]`

## 2) چه چیزی دست نخورده می‌ماند
- id، slug، type، subType، status
- categories / activities / features / facilities / scores
- location و coordinates
- visit (اعداد و enumها) — فقط اگر notes متنی visit پروموشنال/پلتفرمی بود، notes را خنثی کن
- travelChecklist (فقط idهای taxonomy)
- climate / safety.risks (enumها)
- relations / external ids
- **`sources[]`**: URL و type را حذف یا عوض نکن. فقط اگر `title` نام پلتفرم را فریاد می‌زند، عنوان را خنثی کن بدون حذف URL.
- media URL / license / credit / sourceUrl — فقط alt/caption را بازنویس

پس از هر Entity: `save_active_entity` با همان `expectedNodeId`. خطای gate را همان‌جا درست کن؛ Entity بعدی را با خطای باز رها نکن.

## 3) قانون طلایی نوشتن
- Fact از منابع ثبت‌شدهٔ همان Node؛ عدد/تاریخ/قانون را اختراع نکن.
- متن را از نو بنویس؛ چسباندن جملهٔ منبع یا paraphrase مکانیکی ممنوع است.
- نام OTA/امتیاز پلتفرم در متن کاربرمحور ممنوع است (بخش ۵).
- **کیفیت هدف:** خواننده فکر کند یک نویسندهٔ انسانیِ مسلط به مقصد نوشته — نه مدل زبانی، نه ویکی، نه کاتالوگ رزرو.

## 4) ضد اثر «متن AI» (سخت — مهم‌ترین بخش)
مثل ادیتور انسانی بنویس. این ردپاها ممنوع‌اند:

### ۴-۱ ساختار و ریتم
- شروع کلیشه‌ای ممنوع: «در قلب…»، «واقع در…»، «این مکان که…»، «باید دانست که…»، «شایان ذکر است»، «لازم به ذکر است»، «از سوی دیگر»، «در مجموع می‌توان گفت»
- هر پاراگراف را با همان الگوی اسم‌مکان + تعریف عمومی شروع نکن
- طول جمله‌ها را عوض کن: کوتاه، متوسط، گاهی یک جملهٔ بلندِ دقیق — نه سه جملهٔ هم‌اندازه پشت‌سرهم
- لیست‌وار نوشتن داخل description ممنوع مگر واقعاً لازم باشد؛ به‌جاش روایت متصل بنویس
- جمع‌بندی شعاری در انتها نگذار («انتخابی عالی برای…»، «تجربه‌ای متفاوت رقم می‌زند»)

### ۴-۲ واژگان و لحن
- ترجمه از انگلیسی ممنوع حس شود: «ارائه می‌دهد»، «فراهم می‌کند»، «امکان تجربه را می‌دهد»، «به شمار می‌رود» را کم کن یا حذف کن
- صفت‌های توخالی ممنوع: منحصربه‌فرد، چشم‌نواز، دل‌انگیز، رؤیایی، فوق‌العاده، بی‌نظیر، جادویی، ایده‌آل
- پرانتز توضیح‌دهندهٔ زیاد و دونقطه‌های پشت‌سرهم نگذار
- همه‌چیز را متقارن و «کامل» ننویس؛ اگر Fact نداری، همان را نگو — جای خالی را با پرگویی پر نکن
- FAQ را شبیه چت‌بات ننویس («البته!»، «حتماً»، «گزینهٔ مناسبی است»). مستقیم و مشخص جواب بده

### ۴-۳ تنوع بین Entityها
- برای دو مکان هم‌نوع، قالب یکسان ممنوع (همان ترتیب: معرفی → تاریخ → امکانات → نتیجه)
- whyVisit هر Entity باید زاویهٔ متفاوتی داشته باشد، نه جملهٔ قالب با اسم عوض‌شده
- tips را از روی هم کپی نکن؛ فقط نکتهٔ واقعاً مال همان جا

### ۴-۴ خودآزمایی قبل از save
متن را یک‌بار با صدای بلند در ذهن بخوان. اگر شبیه بروشور، ویکی‌ربات، یا پاسخ ChatGPT بود → یک دور دیگر از نو بنویس.
اگر حس کردی «خیلی تمیز و بی‌نقص و متقارن» است → عمداً یک زبری انسانی بده: یک جزئیات ملموس، یک محدودیت واقعی، یک ترتیب غیرقالبی.

### ۴-۵ چه چیزی بماند (انسانیت درست)
- مشاهدهٔ ملموس: مصالح، فاصله، فصل، قانون میزبان، محدودیت واقعی
- اطمینانِ آرام برند پلن‌رو؛ بدون فروشنده بودن
- فارسی نوشتاریِ توصیفی برای content؛ محاوره فقط جایی که واقعاً tip کوتاه خطاب به مسافر است

## 5) ممنوعیت نام پلتفرم در متن کاربرمحور (سخت)
در فیلدهای بخش ۱ هرگز ننویس / اشاره نکن به:
کجارو، جاباما، علی‌بابا، لست‌سکند، فلای‌تودی، اسنپ‌تریپ، Booking، Airbnb و هر OTA/مجلهٔ گردشگری دیگر.

همچنین ممنوع:
- امتیاز ستاره‌ای پلتفرم («۴/۲ از ۵»، «۶۳ رزرو»، «۲۳ نظر»)
- «بر اساس … / طبق سایت رزرو / در سامانهٔ …»
- دامنه یا لینک پلتفرم داخل summary/description/faq/seo/tips/warnings/captions

`sources[]` برای provenance داخلی می‌ماند؛ از روی متن نهایی نباید بشود فهمید تحقیق از کدام OTA آمده.

## 6) Brand Voice (اجباری)
مطابق `brand-voice-guide`:
- همراه آگاه، دقیق، مشاهده‌محور؛ بدون اغراق آژانسی
- توصیف مقصد: نوشتاری و Factمحور
- ممنوع quality-gate: سوپرلتیو، کلیشهٔ گردشگری، نویز تکنولوژی/AI
- پرهیز: بهترین، زیباترین، بهشت گمشده، نگین، می‌باشد/می‌گردد/نمایید
- Brand Voice ≠ متن رباتیک متقارن؛ انسانیت سند برند را جدی بگیر

## 7) Ownership متن (اجباری)
- هر Entity فقط دربارهٔ خودش
- Parent فقط معرفی کوتاه Child؛ بدون ساعت/بلیت/قانون Child
- Child مقالهٔ روستا/شهر را قورت ندهد مگر یک اشارهٔ مکانی کوتاه
- FAQ عملیاتی Child فقط روی همان Child

## 8) ترتیب اجرا
1. اطمینان از notes / scopes استان
2. پیمایش DFS همهٔ Entityهای `output/{province_id}/`
3. برای هر Entity: بازنویسی بخش ۱ با قواعد ۳–۷ → `save_active_entity` → رفع error همان‌جا
4. جستجوی سریع روی output برای نام OTA و الگوهای ۴-۱
5. `validate_province` + گزارش کوتاه (تعداد فایل، بدون ادعای «AI-written»)

## 9) خارج از محدوده
- کشف Entity جدید، media hunting، تغییر taxonomy، minify، commit/push
- Fact تازه بدون منبع
- پاک کردن `sources[]`
- نوشتن در گزارش که متن با مدل زبانی ساخته شده

بعد از این مرحله: `05-final-audit-minify`.

## تحویل (Delivery)
1. همهٔ Entityها با متن بازنویسی‌شده save شده‌اند.
2. متن‌ها انسانی، بدون OTA در لایهٔ کاربرمحور، مطابق brand voice.
3. گزارش کوتاه فارسی: چند فایل عوض شد + تأیید پاک‌بودن نام پلتفرم.
4. **commit نکن** مگر کاربر صریحاً بگوید.
