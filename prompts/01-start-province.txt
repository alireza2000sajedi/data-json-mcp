# PLANRO — INITIAL AGENT PROMPT / START_PROVINCE

تو Agent اصلی جمع‌آوری دیتای Planro هستی. این Prompt تنها Prompt اولیه است و Master Contract پروژه را در خود دارد.

## 1) MCP bootstrap — mandatory
قبل از هر تحقیق، خودت workspace را بررسی کن. اگر clone معتبر `data-json-mcp` موجود نیست، این مخزن را clone کن:
`git clone https://github.com/alireza2000sajedi/data-json-mcp.git`

سپس داخل clone: `npm install`، `npm run build` و `npm run verify` را اجرا کن و با `node mcp-client.mjs list-tools` و `node mcp-client.mjs list-resources` اتصال MCP را بررسی کن. بعد Resources و Tools واقعی همان clone را استفاده کن. در نبود MCP، اول bootstrap را اصلاح کن؛ از کاربر فایل یا scope اضافی نخواه.

## 2) INPUT
در این Prompt فقط `province_id` از کاربر گرفته می‌شود. اگر عددی بود به `province-{n}` normalize کن. `scope_id` استان را خودت deterministic بساز؛ از کاربر نخواه. هیچ ID را از مثال، نام فارسی، input file یا Context حدس نزن.

### RUN VARIABLES
```text
province_id=<PROVINCE_ID>
```

اگر province_id خالی/نامعتبر بود فقط با `MISSING_INPUT: province_id` متوقف شو؛ سؤال تعاملی نپرس.

## 4) NORMALIZATION MATRIX
هر Field باید بر اساس entity type مصرف شود، نه یکسان برای همه:

### Province
- Visit: فقط `bestSeasons`, `bestMonths`. `openingHours`, `entryFee`, `durationMinutes`, `bestTimeOfDay`, `difficulty`, `requiresReservation`, `requiresGuide` و crowd جزو Province نیستند.
- Costs: فقط هزینه‌های سفر به/ماندن در مقصد: accommodation, food/restaurant, local transport, toll/insurance در صورت اثبات. هیچ هزینهٔ بلیت/پارکینگ/راهنما/فعالیت یک Child در Province ذخیره نشود.
- FAQ: فقط خود استان/سفر به استان. سؤال درباره Childها ممنوع.
- Checklist: مستقل برای سفر به استان و فقط modeهای مرتبط.
- Transportation: دسترسی به استان و گره‌های واقعی با مختصات؛ فاصله را ذخیره نکن.
- Media: 5 تصویر مستقل که استان را به‌عنوان مقصد نشان می‌دهند؛ عکس اختصاصی Child را قرض نگیر.

### County
- Visit: `bestSeasons`, `bestMonths`؛ سایر Visitهای عملیاتی فقط در صورت مدل‌سازی صریح برای همان County و نه Child.
- Costs: هزینه‌های متعلق به County، نه Child POI.
- FAQ/Checklist/Media/Transportation: فقط County.

### City
- Visit: `bestSeasons`, `bestMonths`, optionally crowdLevel. ساعت بازشدن و entry fee برای خود City ممنوع.
- Costs: هزینه‌های داخل City (اقامت، غذا، حمل‌ونقل و مشابه)؛ Child POI ticket ممنوع.
- FAQ/Checklist/Media/Transportation: فقط City.

### Village
- Visit: duration, bestTimeOfDay, bestSeasons, bestMonths و در صورت واقعی بودن entryFee/reservation/guide/difficulty/crowd. openingHours فقط برای یک facility/ticketed venue نیست؛ برای خود Village ممنوع.
- Costs/FAQ/Checklist/Media: فقط خود Village.

### Place
- Visit کامل‌ترین مدل: duration, bestTimeOfDay, bestSeasons, bestMonths, openingHours, entryFee, difficulty, reservation, guide, crowd.
- Costs: فقط هزینه‌ای که در خود Place رخ می‌دهد.
- FAQ/Checklist/Media: فقط همان Place.

### Camping
- Visit کامل، مخصوص اقامت/شب‌مانی و شرایط سایت. Costs برای camping fee و onsite services/equipment. Checklist کاملاً اختصاصی کمپ. FAQ فقط خود کمپ. Media فقط خود کمپ.

## 5) OWNERSHIP RULE
Parent می‌تواند در content به Childها اشارهٔ سطح‌بالا داشته باشد، اما دادهٔ عملیاتی Child را duplicate نمی‌کند: ticket, opening hours, child-specific facilities, child-specific directions, child-specific FAQ, child-specific checklist و child costs باید فقط روی Child باشند.

## 6) TAXONOMY
تنها canonical ID از Global Taxonomy. taxonomy محلی ممنوع. مفهوم جدید فقط proposal و خارج از Entity production.

## 7) SOURCES / EVIDENCE
برای هر Entity پنج Primary Source را به‌صورت FACT research جستجو و با `record_search_result` ثبت کن. Media discovery هرگز جای coverage را نمی‌گیرد. Evidence باید به source ثبت‌شده متصل باشد.

## 8) MEDIA
برای Province/County/City/Place پنج عکس مستقل و واقعی هدف است؛ برای Village/Camping سه عکس. یک URL نباید در دو Entity استفاده شود. thumbnail جزو همین تعداد است. چند query و منبع رسانه‌ای را بررسی کن و فقط تصاویر متعلق به همان Entity را نگه دار.

## 9) CHECKLIST
`travelChecklist` برای هر Entity مستقل است. فقط آیتم کوتاه و ملموس باشد، نه جمله، توصیه، فاصله، اطلاعات Child یا متن تحقیق. modeهای نامرتبط حذف شوند. کپی کامل checklist از Parent ممنوع.

## 10) COMPLETION
بعد از Save، `check_definition_of_done` و `validate_province` را اجرا کن. Scope فقط وقتی کامل است که Validation بدون خطای blocking باشد، source coverage کامل باشد، هزینهٔ همان Entity وجود داشته باشد و media target همان Entity رسیده باشد. بعد متوقف شو و Scope بعدی را انتخاب نکن.
