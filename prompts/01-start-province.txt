# PLANRO — INITIAL AGENT PROMPT / START PROVINCE

این فایل Prompt مادرِ شروع پروژه است. بعد از دریافت آن، Agent باید خودش MCP را آماده کند و سپس Province انتخاب‌شده را جمع‌آوری کند.

## 1) MCP bootstrap — اجباری
قبل از هر تحقیق، workspace را بررسی کن. اگر clone معتبر پروژه موجود نیست، خودت اجرا کن:
`git clone https://github.com/alireza2000sajedi/data-json-mcp.git`

سپس داخل clone:
`npm install`
`npm run build`
`npm run verify`
و برای بررسی اتصال:
`node mcp-client.mjs list-tools`
`node mcp-client.mjs list-resources`

فایل‌ها و Resourceهای واقعی را از همان clone بخوان؛ اگر MCP هنوز متصل نیست، مشکل فنی bootstrap را بررسی کن و فقط در صورت غیرقابل‌اجرا بودن با `MCP_UNAVAILABLE` متوقف شو. نبود فایل/Resource را قبل از تلاش برای clone گزارش نکن و از کاربر فایل نخواه.

## 2) ورودی
فقط یک ورودی از کاربر لازم است:
```text
province_id=<PROVINCE_ID>
```
قرارداد ورودی Runtime (authoritative):
- اگر در Task جاری یک مقدار واقعی برای `province_id` آمده باشد (مثلاً `province_id=30` یا حتی فقط عدد `30` در متن درخواست)، همان مقدار authoritative است و placeholderِ `<PROVINCE_ID>` داخل همین فایل را نادیده بگیر.
- placeholder فقط زمانی معنا دارد که هیچ مقدار واقعی در Task نباشد؛ در آن حالت خروجی `MISSING_INPUT: province_id` بده و متوقف شو (سؤال تعاملی نپرس).
- `province_id` عددی مثل `1` را خودت به `province-{n}` تبدیل کن؛ MCP هم همین Normalize را انجام می‌دهد، پس هر دو شکل قابل قبول است.
- `scope_id` استان را خودت deterministic بساز و هرگز از کاربر نخواه.

## 3) منابع لازم
بعد از bootstrap این موارد را بخوان:
- `planro://rules/readme`
- `planro://schema/place`
- `planro://rules/entity-fields`
- `planro://rules/source-policy`
- `planro://rules/brand-voice-guide`
- `planro://taxonomy`
- `planro://scopes`

## 4) تعریف نوع Entity و کاربرد فیلدها
ماتریس قطعی در `planro://rules/entity-fields` است.

### Province
Visit فقط: `bestSeasons`, `bestMonths`.
Opening hours، entry fee، difficulty، guide، reservation، duration و bestTimeOfDay برای خود Province ممنوع است.
FAQ، Checklist، Media، Safety و Transportation فقط در سطح خود استان هستند.
فیلد `costs` حذف شده است؛ قیمت/هزینه را در Entity ذخیره نکن.

### County
Visit فقط bestSeasons/bestMonths.
FAQ/Checklist/Media/Transportation متعلق به خود County؛ child-specific ممنوع.

### City
Visit: bestSeasons/bestMonths و در صورت منبع معتبر crowdLevel.
Opening hours و entry fee و مشخصات عملیاتی Placeهای داخل شهر ممنوع.

### Village
Visit می‌تواند مدت، زمان روز، فصل، ماه، سختی، reservation، guide، crowd و entryFee داشته باشد فقط وقتی خود Village/خدمت متعلق به Village موضوع است؛ openingHours برای خود Village ممنوع.

### Place
Visit کامل: duration، bestTimeOfDay، bestSeasons، bestMonths، openingHours، entryFee، difficulty، reservation، guide، crowd.
FAQ/Checklist/Media فقط برای همین Place.

### Camping
Visit و Checklist و FAQ و Media مخصوص همان محل کمپینگ.

## 5) Ownership
Parent می‌تواند در content به Childها در سطح معرفی اشاره کند، اما نباید operational data را duplicate کند:
- child ticket
- child opening hours
- child facilities
- child directions
- child FAQ
- child checklist

این اطلاعات فقط در Child Entity نگهداری می‌شوند.

## 6) Costs — حذف‌شده
فیلد `costs` و مدل CPI از قرارداد حذف شده‌اند. قیمت حدس نزن و وارد Entity نکن؛ اپ بعداً می‌تواند هزینه را جداگانه مدیریت کند.

## 7) FAQ model
FAQ مستقل است.
Province FAQ درباره سفر و خود استان.
County FAQ درباره خود County.
City FAQ درباره خود City.
Village FAQ درباره خود Village.
Place FAQ درباره خود Place.
Camping FAQ درباره خود Camping.
سؤال‌های child-specific در Parent ممنوع.

## 8) Checklist model
`travelChecklist` برای هر Entity مستقل است و بر اساس حالت سفر (`tour` / `personalCar` / `airplane` / `camping` / `train` / `bus`) پر می‌شود.
آیتم‌ها فقط canonical id از `taxonomy/checklist-items.json` (و Resource `planro://taxonomy`) هستند — مثل `tent`، `sunscreen`، `snow_chains`.
متن آزاد فارسی، جمله، مسیر، قیمت یا توصیه در checklist ممنوع است.
کپی کامل Checklist از Parent/Child ممنوع؛ فقط آیتم‌های واقعاً مرتبط با همان Entity.

## 9) Media model
هر Entity مجموعه عکس مستقل دارد:
- Province: 5 عکس
- County: 5 عکس
- City: 5 عکس
- Place: 5 عکس
- Village: 3 عکس
- Camping: 3 عکس
Thumbnail جزو همین تعداد است.
یک image URL نباید بین دو Entity تکرار شود.
عکس Child/Parent/Sibling برای Entity دیگر قابل استفاده نیست.
برای Province عکس باید واقعاً نماینده خود استان باشد، نه صرفاً یک Place معروف داخل آن.
چند جستجوی مستقل انجام بده و از اولین ۱–۲ عکس متوقف نشو.

## 10) Sources
پنج Primary Source تعریف‌شده در Source Policy را برای هر Node واقعاً بررسی کن و با `record_search_result` ثبت کن؛ no-result/unreachable نیز باید ثبت شود.
Media discovery هرگز جای Fact Source Coverage نیست.
فیلد `evidence` حذف شده است؛ Factها را در `sources[]` و متن Entity نگه دار، نه در آرایهٔ evidence.
متن کاربر نباید شامل query، search engine، یادداشت تحقیق، تناقض منبع یا فرآیند جمع‌آوری باشد.

## 11) Taxonomy
همه type/subType/category/activity/feature/facility/risk و آیتم‌های checklist در Entity تولیدی فقط از Global Taxonomy (`planro://taxonomy`).
اگر مفهوم reusable در Global نبود:
1. مثل خود Taxonomy رفتار کن: تحقیق کن، دادهٔ واقعی بگیر، و یک آیتم کامل taxonomy بساز.
2. آیتم را در کاتالوگ متناظر زیر `taxonomy/agent-taxonomy/` بنویس (همان فایل‌ها: types/subtypes/categories/activities/features/facilities/risks/checklist-items) با همان شکل `id` + `label` (+ `appliesTo`/`group` اگر لازم) و فیلد `source` (provinceId، nodeId، reason، proposedAt، urls).
3. آن id را هنوز وارد Entity تولیدی نکن؛ تا promote انسانی فقط staging است (`planro://taxonomy/agent`).
در پایان مرحلهٔ استان (و اگر در Scope بعدی آیتم تازه‌ای ساختی) صریحاً بگو:
«این مفاهیم در Global Taxonomy نبودند و من در agent-taxonomy ساختم» + فهرست idها و فایل کاتالوگ.
Taxonomy داخل Province/Scope کپی نشود.

## 12) کیفیت متن
فارسی طبیعی، دقیق و واقعی بنویس. متن نباید شبیه گزارش تحقیق یا متن ماشینی باشد. ادعای مطلق/مقایسه‌ای و لحن تبلیغاتی ممنوع است.

## 13) Location / Transport
بهترین مختصات قابل اتکا را بگیر و در صورت وجود bounding box را ثبت کن.
Distance مشتق‌شده را در Entity ذخیره نکن؛ مختصات برای محاسبه در اپ کافی است.
Transport فقط node/route مرتبط با همان Scope باشد.

## 14) Completion
ابتدا `import_province_scopes` را اجرا کن.
سپس فقط Province root را تحقیق کن؛ County/City/Village/Place فرزندان را در این مرحله deep-research نکن.
Province فقط وقتی Complete است که schema، taxonomy، source coverage، normalized fields، FAQ، independent checklist و media target را پاس کند.
سپس `check_definition_of_done` و validation را اجرا کن.
بعد از موفقیت متوقف شو و Scope بعدی را خودکار انتخاب نکن.

## 15) قرارداد ترتیب فراخوانی MCP (Call Order)
ترتیب زیر قرارداد است، نه پیشنهاد:
1. `import_province_scopes(provinceId)` — یک بار؛ idempotent است و درخت County/City/Village را می‌سازد.
2. `get_scope_state` / `get_next_research_node` — Node بعدی را فقط از MCP بگیر؛ ترتیب DFS را خودت حدس نزن.
3. `get_node_context(nodeId)` — قبل از تحقیق، قواعد و وضعیت همان Node را بخوان.
4. `record_search_result(...)` — برای هر پنج Primary Source، حتی وقتی نتیجه‌ای نبود (`resultCount=0` / unreachable).
5. `get_source_coverage(nodeId)` — تا `satisfied=true` نشده سراغ نوشتن Entity نرو.
6. `record_media_candidate(...)` برای هر عکس، سپس `finalize_media(nodeId)` تا به target برسی؛ اگر واقعاً عکس معتبر پیدا نشد `mark_node_media_deficit`.
7. `save_active_entity({provinceId, entity, expectedNodeId})` — ذخیره فقط از این مسیر.
8. `complete_discovery_task({nodeId, count})` — `count` عدد واقعی Nodeهای ثبت‌شده است؛ بدون آن رد می‌شود.
9. `check_definition_of_done(provinceId)` سپس `validate_province(provinceId)`.
10. وقتی `awaitingScopeSelection=true` شد، متوقف شو؛ Scope بعدی را از `planro://scopes/{provinceId}` به کاربر پیشنهاد بده و فقط با `set_active_scope` ادامه بده.
`mark_node_complete` مستقیم وجود ندارد؛ فقط از طریق `update_notes` انجام می‌شود. ابزار `resolve_scope_name` هم حذف شده است: برای تبدیل نام به id از `planro://scopes/{provinceId}` و `indexByName` استفاده کن.

## 16) تحویل (Delivery) — بعد از DoD موفق اجباری است
1. `check_definition_of_done` باید `complete:true` باشد و `validate_province` باید `invalid:0` باشد.
2. اگر DoD یا validation پاس نشد، **commit ممنوع** است؛ فقط تعمیر کن و دوباره همان دو ابزار را بزن.
3. پس از پاس شدن هر دو، خروجی را به git بسپار:
   - `git status --short output/`
   - `git add output/`
   - commit با پیام واضح برای همین Scope
   - `git push` (شکست push مانع commit محلی نیست، ولی تلاش اجباری است)
هرگز `output/` را به `.gitignore` برنگردان.

## 17) RUN VARIABLES — پایین فایل را مستقیم پر کن
```text
province_id=<PROVINCE_ID>
```
هرگز برای Province از کاربر `scope_id`، نام استان یا مسیر فایل درخواست نکن.
