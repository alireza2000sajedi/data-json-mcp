# PLANRO — START PROVINCE (Prompt مادر)

بعد از دریافت این پرامپت: MCP را آماده کن، سپس **فقط Province root** را کامل کن و برای Scope بعدی بایست.

Entityهای پایپ‌لاین: **Province / County / City / Village / Place**.
محل کمپ = Place (مثلاً `subType: campground`) — Entity جدا نساز.

---

## 0) RUN VARIABLES
```text
province_id=<PROVINCE_ID>
```
- مقدار واقعی در Task (عدد یا شکل `province-{n}`) authoritative است؛ placeholder را نادیده بگیر.
- نبود مقدار → `MISSING_INPUT: province_id` و توقف؛ سؤال نپرس.
- عدد را به `province-{n}` normalize کن.
- `scope_id` / نام استان / مسیر فایل از کاربر نخواه.

## 8) متن انسانی — کیفیت نهایی از همان save اول
مرجع: `planro://rules/brand-voice-guide`. پاس بازنویسی جدا ممنوع؛ متن Entity از اول باید نهایی باشد.

قانون طلایی:
- Fact فقط از منابع همان Node؛ عدد/تاریخ اختراع نکن
- از نو بنویس؛ کپی منبع / paraphrase مکانیکی ممنوع
- خواننده باید حس کند یک ادیتور انسانی نوشته — نه مدل، نه ویکی، نه کاتالوگ رزرو

ضد اثر AI (سخت):
- شروع کلیشه‌ای ممنوع: «در قلب…»، «واقع در…»، «شایان ذکر است»، «لازم به ذکر است»
- صفت توخالی ممنوع: منحصربه‌فرد، رؤیایی، بهشت گمشده، نگین، چشم‌نواز، جادویی، بی‌نظیر
- ریتم جمله‌ها یکنواخت نباشد؛ description را لیست‌وار ننویس
- whyVisit و tips را بین Entityهای هم‌نوع کپی نکن
- FAQ مثل چت‌بات نباشد («البته!» / «حتماً»)
- حس بروشور/ChatGPT → یک دور از نو بنویس

OTA در متن کاربرمحور ممنوع (کجارو/جاباما/علی‌بابا/لست‌سکند/فلای‌تودی و امتیاز/رزرو پلتفرم). فقط در `sources[]`.

Ownership متن: Parent فقط معرفی کوتاه Child؛ بدون ساعت/بلیت/FAQ عملیاتی Child.

## 9) Location + سلسله‌مراتب (قفل)
اگر `input/{n}.json` یا `planro://scopes/{provinceId}` برای همان Node فیلد `location` (lat/lng) داشت، **همان را مبنای مختصات Entity بگذار** و فقط در صورت نبود/بی‌اعتباری، Nominatim/OSM را برای تکمیل (مثلاً boundingbox) استفاده کن.
مختصات قابل‌اتکا؛ Distance مشتق ذخیره نکن.

### فقط از input — واحد اداری
County / City / Village را **فقط از `input/{n}.json`** بگیر (`import_province_scopes` / `planro://scopes`).
- City یا Village جدید به چک‌لیست اضافه نکن.
- اگر واحد اداری در input نبود → نادیده بگیر؛ از خودت شهرستان/شهر/روستا نساز.

### Place = تحقیق اجباری (چک‌لیست فقط بذر است)
`places` / `placesChecklist` در input فقط **اولویت و نقطهٔ شروع** است — سقف نیست.
- `import_province_scopes` هر Place چک‌لیست را به‌صورت Node در صف DFS seed می‌کند — هر کدام باید entity کامل بگیرند (sources + media + Visit).
- برای Placeهای seed‌شده **id جدید reserve نکن**؛ همان `place-*` موجود در `list_pending_nodes` / `get_node_context` را save کن.
- `reserve_entity_id` فقط برای Place **فراتر از checklist**؛ بعد `register_node` با Parent درست.
- اول همهٔ نام‌های checklist را با `location` (اگر هست) پوشش بده و save کن.
- بعد **حتماً** وب را برای جاذبه‌های واقعی همان Parent جستجو کن؛ Place اضافه را زیر Parent موجود بساز.
- **MCP رد می‌کند:** `complete_discovery_task` برای `places`/`countyPlaces`/`provincePlaces` با `count` کمتر از طول checklist (`PLACES_BELOW_CHECKLIST`).
- **MCP رد می‌کند:** `count:0` وقتی checklist خالی است بدون حداقل ۳ جستجوی کشف Place (`PLACES_ZERO_WITHOUT_SEARCH`).
- DoD تا وقتی نامی از checklist بدون Entity فعال مانده `complete:false` می‌ماند (`uncoveredChecklistPlaces`).
- ممنوع به‌عنوان Place: مسجد محلی معمولی، مغازه، پمپ‌بنزین، صافکاری، اداره، مدرسه، بیمارستان، رستوران زنجیره‌ای بی‌اهمیت گردشگری.
- مجاز: اثر تاریخی شاخص، موزه، بازار تاریخی، کاخ، قلعه، آبشار، غار، دریاچه، پارک ملی/جنگلی مهم، زیارتگاه معروف گردشگری، پل/برج نمادین، محوطهٔ باستان‌شناسی، کمپینگ شاخص (`campground`).

### Parent روستا
Village هرگز فقط به Province وصل نشود. Parent همان است که در input آمده:
- `counties[].villages` → Parent = **County**
- `counties[].cities[].villages` → Parent = **City**

### روستا ≠ Place
1. اول **Village** را از input کامل کن (entity + media=۲).
2. جاذبه‌ها را به‌عنوان **Place زیر همان Village** attach کن.
3. ممنوع: `روستای X` یا نام خود روستا به‌عنوان Place.

در Entity، `location.province / county / city / village` را مطابق زنجیرهٔ scopes پر کن.

## 11) Completion این پرامپت — فقط Province root
1. `import_province_scopes(provinceId)` — درخت County/City/Village از input؛ deep-research نکن.
2. فقط Node استان را کامل کن (entity + sources + FAQ + checklist + media=۵ + متن نهایی).
3. track `provincePlaces` را با count واقعی ببند (۰ اگر Place سطح استان نبود). County/City/Village را deep-research نکن.
4. `check_definition_of_done` + `validate_province`
5. وقتی `awaitingScopeSelection=true` → برای **ادامهٔ کامل استان بدون Scope** برو به `07-full-province-places.txt` (فقط `province_id`؛ Scope نپرس).
6. `02-run-scope.txt` فقط اگر کاربر صریحاً یک شهرستان/شهر/روستا خواست. پایان کار استان: `05`.

---

## 12) Call Order (قرارداد)
1. `import_province_scopes(provinceId)`
2. `get_next_research_node` / `get_scope_state` — ترتیب را حدس نزن
3. `get_node_context(nodeId)`
4. `record_search_result` × ۵ Primary
5. `get_source_coverage` → `satisfied:true`
6. `record_media_candidate` → `finalize_media` تا target
7. `save_active_entity({ provinceId, entity, expectedNodeId })`
8. `complete_discovery_task({ nodeId, track, count })` — برای Place: count ≥ طول checklist؛ صفر فقط با جستجوی واقعی
9. `check_definition_of_done` → `validate_province`
10. `awaitingScopeSelection=true` → اگر Task بعدی `07` است Scope نپرس؛ وگرنه برای یک Scope اختیاری بایست

`mark_node_complete` مستقیم نیست. نام→id از `planro://scopes/{provinceId}` / `indexByName`.
