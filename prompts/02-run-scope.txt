# PLANRO — RUN ONE SCOPE

قرارداد اصلی در `01-start-province.txt` است. فقط همین Scope را اجرا کن.
یک Scope یعنی کل زیردرخت آن واحد (خود واحد + شهرها/روستاها/مکان‌هایش)، نه فقط ریشه.

### RUN VARIABLES
```text
province_id=<PROVINCE_ID>
scope_id=<SCOPE_ID>
```
اگر در Task جاری مقدار واقعی `scope_id` آمده باشد، همان authoritative است و placeholder بالا نادیده گرفته می‌شود؛ در نبود مقدار واقعی `MISSING_INPUT: scope_id` بده و متوقف شو.

- MCP و Resourceها را بررسی کن.
- Scope را دقیقاً lock کن (`set_active_scope`) و فقط subtree مجاز آن را اجرا کن؛ صف کار را با `list_pending_nodes` ببین (پیش‌فرض همان Scope؛ `allScopes:true` برای کل استان).
- Field policy را از `planro://rules/entity-fields` بخوان.
- Visit/FAQ/Checklist/Media باید متعلق به همان Entity باشند.
- برای Province/County/City openingHours و child-specific entryFee ذخیره نکن.
- برای Parent هزینه Child یا FAQ Child ذخیره نکن.
- هر Entity checklist مستقل خودش را داشته باشد.
- Media: Province/County/City/Place = 5؛ Village/Camping = 3؛ بدون URL تکراری بین Entityها.
- پنج Primary Source را واقعاً جست‌وجو و با `record_search_result` ثبت کن؛ Media جای Source Coverage نیست.
- فقط canonical taxonomy IDs از Global Taxonomy را در Entity استفاده کن.
- اگر id لازم در Global نبود → مثل Taxonomy آیتم بساز داخل `taxonomy/agent-taxonomy/{catalog}.json` (با `source` و دادهٔ واقعی)؛ وارد Entity نکن. در گزارش پایان Scope بگو چه نبود و چه ساخته شد.
- SPEED MODE از پرامپت ۰۱ فعال است: تحقیق موازی OK؛ save/DoD/git خطی؛ بدون حذف Source/media/subtree.
- Save فقط با MCP؛ سپس DoD + validation و توقف.

## تحویل (Delivery)
1. `check_definition_of_done` → `complete:true` و `validate_province` → `invalid:0`.
2. اگر DoD پاس نشد، **commit ممنوع**.
3. پس از پاس: `git status --short output/` → `git add output/` → commit → `git push`.

اگر متغیر ناقص است `MISSING_INPUT: <variable>` بده؛ سؤال نپرس.
