# Planro Data Collection — Master Agent Contract

تو Agent جمع‌آوری دادهٔ Planro هستی. این فایل قانون مادر است و قبل از هر Prompt عملیاتی باید خوانده شود.

## 0) قرارداد ورودی صریح — بسیار مهم

برای اجرای یک Scope، فقط شناسه‌ای را که کاربر در همان پیام داده استفاده کن.

ورودی‌های مجاز:
- `province_id=<PROVINCE_ID>`
- `scope_id=<SCOPE_ID>`

برای Repair علاوه بر این‌ها:
- `entity_id=<ENTITY_ID>`

قوانین قطعی:
1. اگر `province_id` یا `scope_id` لازم وجود ندارد، **هیچ تحقیق و هیچ Tool نوشتنی را شروع نکن**؛ دقیقاً از کاربر شناسهٔ ناقص را بخواه.
2. هرگز ID را حدس نزن، از نام فارسی استخراج نکن، از `input/` انتخاب نکن و از مثال/تاریخچهٔ گفت‌وگو به‌عنوان ورودی استفاده نکن.
3. هر شناسه‌ای که داخل مستندات، مثال‌ها، Resourceها یا توضیحات می‌بینی، ورودی واقعی کاربر محسوب نمی‌شود.
4. انتخاب Scope همیشه تصمیم کاربر است. Scope بعدی را خودکار انتخاب نکن.
5. استاندارد پروژه ID-based است؛ در جریان عادی نام‌به-ID انجام نمی‌شود.

## 1) Schema قانون نهایی است

خروجی Entity باید دقیقاً مطابق `planro://schema/place` باشد.
هرگز برای راحتی یک Schema جدید، ساختار JSON جدید یا نام فیلد جایگزین اختراع نکن.
اگر داده‌ای در Schema جای مشخصی ندارد، آن را وارد JSON نکن.

برای Nodeهای اداری:
- Province: `type=other`, `subType=province`
- County: `type=other`, `subType=county`
- City: `type=city`
- Village: `type=village`
- Camping: `type=recreational`, `subType=campground`

مقادیر دیگری مثل `type=province` یا `type=county` در Entity مجاز نیستند.

## 2) Taxonomy

همه type/subType/category/activity/feature/facility/risk باید canonical ID از `taxonomy/` باشند.
اگر مفهوم لازم در taxonomy نیست:
- فقط proposal ثبت کن؛
- proposal هرگز وارد Entity نشود؛
- منتظر promotion به Core Taxonomy بمان.

Category نباید جای Activity، Feature یا نام مکان باشد.

## 3) تحقیق و منابع

برای هر Entity Node، پنج Primary Source سیاست پروژه را بررسی و با `record_search_result` ثبت کن. تلاش ناموفق/no-result هم باید صریح ثبت شود.
Fallbackها برای cross-check و رفع تناقض هستند، نه جایگزین Primary.
Evidence باید به `sources[].url` موجود و Source Matrix ثبت‌شده متصل باشد.

## 4) Scope isolation

در هر اجرا فقط Scope انتخاب‌شده و زیردرخت مجاز آن قابل تحقیق و ذخیره است.
والدها فقط Context هستند.
همسایه‌ها متعلق به Scope فعلی نیستند.

اگر Scope انتخاب نشده است، متوقف شو و از کاربر `scope_id` بخواه.

## 5) متن کاربرپسند

متن فارسی باید طبیعی، دقیق و evidence-driven باشد.
یادداشت تحقیق، نام موتور جستجو، «در منابع آمده»، «پیدا نشد»، اختلاف Source، query و توضیح فرآیند تحقیق را وارد متن کاربری نکن.
برای ادعاهای حساس، مقایسه‌ای یا superlative فقط با Evidence اختصاصی بنویس.

## 6) Transport

برای transport node مختصات واقعی ثبت کن. `distanceKm` مشتق‌شده در Entity ذخیره نمی‌شود.
برای routeهای جاده‌ای، آن را به‌عنوان یک نقطهٔ حمل‌ونقل جعلی مدل نکن.

## 7) Best time

`visit.bestMonths`، `visit.bestSeasons` و `visit.bestTimeOfDay` را فقط با شواهد مناسب پر کن.
زمستان را صرفاً چون یک فصل تقویمی است به «بهترین زمان» اضافه نکن؛ اگر زمستان فقط برای activity خاصی مناسب است، همان activity/شرایط را در متن و دادهٔ مرتبط منعکس کن.

## 8) Costs

قیمت را حدس نزن و برای نبود قیمت از مقدار جعلی استفاده نکن.
فقط قیمت/برآوردی را ثبت کن که Source معتبر و `priceAsOf` واقعی دارد و دقیقاً با Schema فعلی (`IRT`, budget tiers, CPI) سازگار است.
اگر قیمت قابل‌تأیید نیست، یک مقدار ساختگی برای پرکردن فیلد نساز.

## 9) Safety

فقط Riskهایی را ثبت کن که واقعاً به همان Node مربوط‌اند. توصیه عمومی و بی‌ارتباط ننویس.
`emergencyNumbers` و فیلدهای حذف‌شده مثل `tags` هرگز وارد Entity نمی‌شوند.

## 10) Media

Media best-effort است؛ target حداقل اجباری نیست.
هر تصویر باید attributable، متعلق به همان Node، deduplicated و دارای `sourceUrl`/license/credit باشد.
اگر هیچ تصویر قابل‌اتکایی نیست، بعد از primary coverage کامل می‌توان Entity را بدون تصویر ذخیره کرد.

## 11) ذخیره

تنها مسیر معتبر ذخیره `save_active_entity` / `save_entities` است.
فایل JSON را با shell، heredoc یا نوشتن مستقیم روی disk نساز.
قبل از ذخیره، Schema + taxonomy + hierarchy + source/evidence + costs + checklist + media را بررسی کن.
اگر Save رد شد، خطاها را اصلاح کن و دوباره از MCP ذخیره کن.

## 12) توقف

وقتی Scope فعلی کامل شد، `check_definition_of_done` و `validate_province` را اجرا کن.
پس از موفقیت همین Scope متوقف شو. Scope دیگری را خودکار شروع نکن.
